## 这是什么

一本可以玩的人生账本。

原书《高性价比人生指南》里有 672 条循证建议，每条都带成本、收益、证据等级和原始出处。这个项目把它做成了一款浏览器 3D 游戏：**人生里的坑从井口掉下来，你用手上的建议卡把它挡掉，每一手都记进你的净值。**

输了不会真的死，但你会看到那口井里堆着什么，以及哪一条建议本来能救你。

## 三十秒上手

```bash
npm install
npm run dev        # http://localhost:3100
```

打开先选模式：**以身入局**（直接查）或**游戏人生**（玩一局）。右上角随时切。

**以身入局**：说人话就行。按 `/` 直接进；也可以用 `?q=你的问题`
把一次检索当链接分享出去。

**游戏人生**：点「开始」之后

- **点卡片**（或按 `1` `2` `3`）出一张牌
- **长按卡片**看这条建议的完整内容（电脑上是把鼠标停在卡片上）
- **空格**放过这一手
- **暂停**：左下角，或按 `P`。方块会停在半空，慢慢读那三张卡
- **结束**：左下角。不想玩了就直接收局

## 两种模式

打开之后先选一个。右上角随时能切，游戏进度不丢（只是冻住）。

![入口](docs/shot-start.png)

**以身入局**：不打游戏，直接查。说你遇到什么事（「房东不退我押金怎么办」），
从 672 条里翻出真正管用的那条，连成本、证据、原始出处一起给你。

![以身入局](docs/shot-lookup.png)

**游戏人生**：玩一局。风险从井口掉下来，你手上三张卡，每个只有一次机会。

### 检索是怎么做的

两段，因为单靠哪一段都不行：

1. **本地召回**（离线，毫秒级）。672 张卡 + 284 个风险建一份索引，中文用
   「单字 + 二元组」切词，配 IDF 压高频字，标题命中额外加权。
   实测 15 个手写用例全部命中前 5，平均查询 3.9ms。
2. **Jev 复核**（classifier.dev，一次请求）。把本地前 50 条送过去，按三档判相关性：
   `直接回答了这个问题` / `沾边但不直接` / `完全无关`。Jev 说「直接回答了」的排到最前。

抄的是 Jev（System One）那套格式规范：判断要窄、标签用自然语言词、
**必须留「都不匹配」的出口**（classifier.dev 永远会返回你给的某个标签，
没有出口再不相干的文本也会被自信地塞进最像的那一类）、粗筛偏保守。

两个坑，代码注释里也写了：

- **`confidence` 和 `scores` 现在常常是 `null`**（它的后端模型换过），
  所以排序不能依赖置信度阈值，只能用 label；排序交给本地分。
- **匿名调用会被拦。** 实测从数据中心出口 IP 访问会返回
  `403 proxy_requires_payment` 或 `402 request_spending_limit`。所以本地那一段是**必须**的：
  Jev 不可用时功能照常，状态行会如实说明，绝不假装 Jev 判过。
  正常住宅网络的访问者不受影响。

## 玩法：一口井，三张卡，一次机会

**① 井口掉下一个风险。**
一共 **284 个**，全部从原书 34 章里铺出来：车祸、押金要不回、替人担保、自动续费、
粉尘车间的职业病、孩子的近视、亲人的身后事、头孢配酒。
标题下面那句是它的**情境**，先读它。

**② 你手上三张卡，每张是原书的一条建议。**
牌面只标两样：三项成本（**钱 / 时间 / 毅力**）和**证据等级**。
**没有分类标签，也没有和风险呼应的颜色。**

**③ 挑出真正能接住这个风险的那一条。**
三条里只有一条是原书明确指向它的，另外两条从别的域抽，讲的是别的事。
判断依据只能是内容。

**④ 每个风险只有一次机会。**
点错了，方块直接砸下去，井里多一层，进下一个风险。
**没有第二次机会，这不是难度，是设计。**

**⑤ 不管选对选错，都会弹一张讲解卡。**
把原书那条建议的「说人话 / 收益 / 备注 / 证据 / 来源」讲完，读完点「继续」，下一手才开始。
选错的话，先说你选的那条讲的是别的事，再亮出正确的那条。

**⑥ 撑满 19 手、井没堆满 10 层，这本账就算结得漂亮。**
井满了就提前结束，结算页会告诉你死在哪一条，以及哪几条建议本来能救你。

### 题库有多大

| | 数量 |
|---|---|
| 原书条目 | 672 |
| 风险（井口掉下来的那些） | **284**，覆盖全部 34 章 |
| 被用作答案的条目 | **503**（75%） |
| 每手发牌 | 1 张原书明确指向的答案，加 2 张别的域的干扰项 |

一局 19 手，从 284 个风险里抽，不会撞车。`npm run verify:risks` 会对着
`public/cards.json` 硬校验每一条答案卡的条号，写错就构建失败。

### 为什么是「账」

因为你手上的东西本来就是有限的：

| 资源 | 起始 | 上限 | 每手回 |
|---|---|---|---|
| 钱 | 8 | 12 | +2 |
| 时间 | 6 | 10 | +2 |
| **毅力** | **4** | **8** | **+1** |

原书里 529 条不花钱、529 条顺手，真正稀缺的只有**毅力**。所以这游戏的核心不是「能不能做」，是「值不值得做」。

每一次决策都有成本和收益，那就该记账。

## 记账科目

净值不是随便给的，是六栏加起来。每一手的数字都不一样，但你不用自己算。

![记账科目](docs/rules.svg)

| 科目 | 记什么 | 记多少 |
|---|---|---|
| 起始 | 开局就有的底子 | **88** |
| 活过一手 | 活着本身就有分，漏掉也给 | **+8** |
| 打掉风险 | 这一手真的把问题解决了 | **+16** |
| 证据等级 | 原书自带。卡越硬，救你救得越漂亮 | **A +8 / B +5 / C +2** |
| 从容出手 | 出手时方块还在上半段 / 中段 / 最后关头 | **+8 / +4 / +1** |
| 连击 | 连着打掉风险，每多一手多 +2，断一次归零 | **封顶 +10** |

**19 手满分 = 1008。** 全 A 卡、全从容、连击不断才拿得到。一般好局落在 850 到 950 之间。

几个设计上的选择：

- **「从容」看的是方块落到哪了，不是绝对秒数。** 下落速度每一手都在变（从 24 秒一路压到 12.8 秒），用秒数算不公平。
- **连击断一次就归零。** 顺境是复利的，逆境的代价也是。
- **发牌保证手上一定有一张原书指向的答案，而且优先挑付得起的。** 答案不在手上就只能靠运气；答案在手上但永远出不起，那就是死局。
- **干扰项从别的域抽。** 同域干扰项会让玩家退回去猜分类，跨域才能逼出「读懂再选」。
- **每次决策后强制读讲解。** 不读完不开下一手。这是这个游戏唯一真正「教」的地方，被跳过去就等于没做。

## 技术栈

| | |
|---|---|
| 语言 | TypeScript，无框架，运行时只依赖 three |
| 3D | Three.js + EffectComposer（半分辨率泛光） |
| 构建 | Vite |
| 数据 | 构建期把 672 条 markdown 解析成静态 JSON，运行时 fetch |
| 字体 | 系统字体栈，不下载外部字体 |

```
src/
  engine.ts          纯逻辑：回合、资源、计分、结算。不碰 DOM，不碰 3D
  main.ts            接线层：引擎事件 → HUD / 场景 / 提示
  data/              域的配色与成本换算表
  scene/
    WellScene.ts     井、手牌、下落、碎裂、相机取景
    textures.ts      卡面 / 层贴图 / 分享图，全部 Canvas 现画
tools/
  build-cards.mjs    解析原书 markdown → public/cards.json
  verify-*.cjs       四个验证脚本
public/cards.json    672 条，1.8MB
```

**引擎和场景是分开的。** 引擎不认识 Three.js，场景不认识规则。两边只通过几个事件来回传，所以计分规则能在无头环境里被完整验证，不用等渲染。

## 验证

不是「跑起来看着没报错」，是四个会真的断言、失败就退非零退出码的脚本：

```bash
npm run verify:risks     # 题库自检：每条答案卡的条号必须真实存在、
                         # 标题长度、章节覆盖、答案卡覆盖率
npm run verify:search    # 检索：15 个手写用例的命中率与耗时，
                         # 以及 Jev 复核的请求形状、判定解析、排序合成、
                         # 403 时的降级（用桩验逻辑，不假装验了线上）
npm run verify:score     # 规则：满分 1008、每手加分构成、连击递增与归零、
                         # 判定按原书答案、发牌保底、一局内风险不重复、
                         # 讲解卡 hold、暂停、结束、重开
npm run verify:preview   # 预览交互：真实触摸滑动与循环、点空白退出、
                         # 三张选项呈现一致、滑动不能被浏览器 pointercancel 打断
npm run verify:flow      # 完整流程：出牌、放过、堆满 10 层、导出分享图
npm run verify:stack     # 逐层检查，确认方块真的往上堆而不是重叠
```

脚本用 Playwright 的 headless shell 跑，需要 `NODE_PATH` 指向装有 `playwright-core` 的目录。

**手机端交互一律用真实触摸事件**（CDP `Input.dispatchTouchEvent`）驱动。
Playwright 的 `mouse.*` 产生的是鼠标事件，不经过浏览器的手势仲裁，用它测滑动会得到假绿：
横滑被浏览器抢走手势、页面收到 `pointercancel`、面板根本换不了张，而鼠标测法照样「通过」。

## 已知取舍

- **牌面不显示「域」，风险条上的域标签也不用该域的颜色。** 一开始是显示的，结果玩家一眼配对颜色就完事，根本不用读内容。分类退回成内部字段，只用来发牌和判分。
- **判定用的是原书明确指向的那几条（`risk.keys`），不是「同域就行」。** 同域判定会让「每天补维生素」接住「高血压」，那就什么都学不到。
- **风险池是手写的数据，不是自动生成的。** 从 672 条建议里反过来写「不做这件事会怎样」，机器做不可靠，所以一条条写，再用 `verify:risks` 把条号钉死。
- **一锤定音是有意的。** 真实的人生不给试错，所以这里也不给。
- **每次决策后强制读一段讲解。** 不读完不开下一手，这是这个游戏唯一真正「教」的地方。
- **19 手和 10 层是配着满分 1008 一起调出来的**，改一个要连着改另一个。
- **3D 用固定步长**（单帧 `delta` 上限 0.05 秒）。极低帧率的机器上动画会慢下来，换来的是逻辑不会因为一帧卡顿就乱跳。
- **镜头不能自由旋转**，只做正负 3 度的视差。井是要看层数的，转起来反而看不清。
- **半分辨率泛光必须在 `EffectComposer.addPass()` 之后再 `setSize`**，因为 `addPass` 会把 pass 尺寸重置成整屏。这个坑踩过两次。
